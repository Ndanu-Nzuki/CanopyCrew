# Contributing to CanopyCrew

Thank you for contributing to CanopyCrew!

## Development Workflow

1. Pull the latest changes from `main`.
2. Create a personal feature branch.
3. Work only within your assigned component or area.
4. Test your changes locally.
5. Commit your changes with descriptive messages.
6. Open a Pull Request into `main`.
7. Wait for review and approval before merging.

## Branch Naming

Use the following naming convention:

- feature/feature-name
- fix/issue-name
- docs/documentation-name
- test/test-name

## Code Ownership

- Frontend: frontend/
- Backend: backend/
- AI Agent: backend/app/agent/
- Species Research: data/species/
- Documentation: docs/

## Shared Files

The following files should not be changed without
coordination with the team:

- README.md
- LICENSE
- .gitignore
- .env.example
- Configuration files
- API contracts
- Database schema

## Code Standards

- Use JavaScript for the frontend.
- Use Python for the backend.
- Keep components modular and reusable.
- Keep API requests separate from UI components.
- Never commit API keys, passwords or secrets.
- Write tests for new functionality where applicable.

## Pull Requests

Every Pull Request should include:

- A clear description of the change.
- The component or feature affected.
- Testing performed.
- Screenshots for significant UI changes.
- Any relevant issues or dependencies.

All changes to main must go through review.
